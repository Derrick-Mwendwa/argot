# Argot

Argot is a small, **zero-dependency** Kotlin library for parsing command-line arguments. You declare
your CLI parameters once and get typed, validated values at startup — inspired by Apple's
[swift-argument-parser](https://github.com/apple/swift-argument-parser). Argot offers **two
consumer-facing styles that share a single parsing engine**, so behavior and `--help` output are
identical no matter which you pick:

- **Delegate style** — pure Kotlin `by` delegates, no code generation. Needs only `argot-core`.
- **Annotation style** — annotate a data class; a KSP processor generates a typed parser at compile
  time. No runtime reflection.

### Design guarantees

- **Zero third-party runtime dependencies.** `argot-core` and `argot-annotations` depend only on the
  Kotlin standard library — no `kotlin-reflect`, no Guava, nothing.
- **No runtime reflection, anywhere.** Delegates are a language feature; the annotation style emits
  explicit code at compile time.
- **Compile-time tooling stays at compile time.** KSP and KotlinPoet live only in `argot-processor`
  and never reach a consumer's runtime classpath.
- Explicit API, KDoc on every public symbol, deterministic generated code, JVM-first (with the few
  JVM touch-points isolated so a Kotlin Multiplatform port stays feasible).

## Modules

| Artifact                      | What it is                                            | Consumer needs it for |
|-------------------------------|-------------------------------------------------------|-----------------------|
| `org.draftcode:argot-core`    | Parsing engine + delegate-style API                   | Both styles           |
| `org.draftcode:argot-annotations` | The `@Command`/`@Option`/`@Flag`/`@Argument` annotations | Annotation style |
| `org.draftcode:argot-processor`   | KSP2 processor that generates parsers (compile-time only) | Annotation style |

## Quick start — delegate style

Only `argot-core` is required.

```kotlin
// build.gradle.kts
repositories { mavenCentral() }

dependencies {
    implementation("org.draftcode:argot-core:0.1.0")
}
```

```kotlin
import org.draftcode.argot.Arguments
import org.draftcode.argot.parsed

class ServerArgs : Arguments(programName = "serve", description = "Run the server") {
    val host: String        by option("--host", help = "Bind host").default("0.0.0.0")
    val port: Int           by option("--port", "-p", help = "Port").int().required()
    val verbose: Boolean    by flag("--verbose", "-v", help = "Verbose logging")
    val files: List<String> by argument(help = "Files to serve").multiple()
}

fun main(argv: Array<String>) {
    val args = ServerArgs().parsed(argv)   // validates; prints help / exits on --help or error
    println("serving ${args.files} on ${args.host}:${args.port} (verbose=${args.verbose})")
}
```

The builder DSL supports `.int()/.long()/.double()/.enum<E>()/.convert(...)` for the value type and
`.default(...)/.required()/.multiple()/.optional()` for cardinality. The terminal call drives the
delegated type: a bare `option(...)` backs a nullable property, while `.required()`/`.default(...)`
back a non-null one. Reading a property before parsing fails fast.

## Quick start — annotation style

Needs `argot-annotations` + `argot-core` and the KSP plugin wired to `argot-processor`.

```kotlin
// build.gradle.kts
plugins {
    kotlin("jvm") version "2.3.20"
    id("com.google.devtools.ksp") version "2.3.9"
}

repositories { mavenCentral() }

dependencies {
    implementation("org.draftcode:argot-core:0.1.0")
    implementation("org.draftcode:argot-annotations:0.1.0")
    ksp("org.draftcode:argot-processor:0.1.0")
}
```

```kotlin
import org.draftcode.argot.annotations.Argument
import org.draftcode.argot.annotations.Command
import org.draftcode.argot.annotations.Flag
import org.draftcode.argot.annotations.Option
import org.draftcode.argot.cli

@Command(name = "serve", description = "Run the server")
data class ServeArgs(
    @Option(names = ["--host"], help = "Bind host", default = "0.0.0.0") val host: String,
    @Option(names = ["--port", "-p"], help = "Port") val port: Int,        // required: non-null, no default
    @Flag(names = ["--verbose", "-v"], help = "Verbose") val verbose: Boolean = false,
    @Argument(help = "Files to serve") val files: List<String>,            // trailing positional list
)

fun main(argv: Array<String>) {
    val args = cli { parseServeArgs(argv) }   // parseServeArgs is generated by Argot
    println("serving ${args.files} on ${args.host}:${args.port} (verbose=${args.verbose})")
}
```

The processor generates a sibling `parseServeArgs(argv: Array<String>): ServeArgs` function — it
never modifies your class. Optionality is inferred from what KSP can see: a non-nullable parameter
with no annotation `default` is **required**; a nullable type is **optional** (`null` when absent);
`@Option(default = "...")` is optional with that default; a `List<T>` parameter is a trailing
positional / repeatable option. The processor reports clear compile errors for duplicate names,
misplaced positionals, `@Flag` on a non-`Boolean`, unsupported types, and a non-nullable parameter
whose Kotlin default Argot cannot read (add `default = "..."` or make the type nullable).

## `--help` output

Both styles render the same deterministic, aligned help via the engine:

```
Run the server

Usage: serve [options] [<files>...]

Options:
  --host <String>   Bind host (default: 0.0.0.0)
  --port, -p <Int>  Port (required)
  --verbose, -v     Verbose logging
  -h, --help        Show this help message and exit

Arguments:
  <files>           Files to serve
```

## Parsing semantics

- Long options: `--name value` and `--name=value`.
- Short options: `-n value`, `-n=value`, attached `-nVALUE`, and combined flag clusters `-abc`.
- `--` terminates option parsing; everything after it is positional.
- A repeated single-valued option is an error; a `multiple` option accumulates into a list.
- Positionals are consumed left to right; one trailing `multiple` positional captures the rest.
- `--help`/`-h` is always recognized; `--version` is recognized when a version is configured.

`ArgotEngine.parse(spec, argv)` is pure: it never prints and never exits. `--help`/`--version` are
surfaced as `HelpRequested`/`VersionRequested`, and input problems as a sealed `ArgotParseException`.
The `cli { ... }` wrapper (and `Arguments.parsed`) adapt those to stdout/stderr and an exit code.

## Toolchain & compatibility

Argot pins the latest mutually-compatible **Kotlin 2.3.20 / KSP 2.3.9 / KotlinPoet 2.3.0** set (the
latest published KSP targets Kotlin 2.3.20). Consumers using the annotation style should apply a
matching Kotlin + KSP version. JDK 17 toolchain.

## Building from source

```sh
./gradlew build      # compiles every module and runs all tests
./gradlew :sample:run --args="greet --name Ada --count 2 --shout"
./gradlew :sample:run --args="serve --port 8080 a.txt b.txt"
```

The `sample` module demonstrates both styles in one app and doubles as an integration test.
